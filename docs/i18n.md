# Internacionalização (i18n)

A interface está disponível em **Português (PT-BR)**, **Inglês (EN)** e **Espanhol (ES)**.
O texto-fonte nos templates é o próprio português; a tradução é feita por *lookup* de
string em **`translations.py`**.

## Como funciona

- `translations.py` tem `SUPPORTED = ("pt", "en", "es")` e três dicionários:
  `_EN`, `_ES` (tradução completa, **mesma quantidade de chaves**) e `_PT`
  (só *overrides* do PT — hoje a troca **Spool → Rolo**; o resto do PT é a própria chave).
- `get_translator(lang)` devolve a função `_()`. Nos templates use `{{ _('texto') }}`;
  no `app.py` (flashes/erros, fora do template) use `t('texto')` — ambos resolvem pelo
  idioma da sessão (`session['lang']`, default `pt`).
- Strings com valores dinâmicos usam *placeholders* nomeados: a chave inclui `{n}`/`{code}`
  etc. e o código faz `t("...{n}...").format(n=...)`.
- O seletor de idioma fica no `templates/base.html`; a bandeira é um **SVG** em
  `static/flags/<código>.svg` (emoji de bandeira não renderiza no Windows).

## Adicionar um novo idioma (ex.: francês `fr`)

1. `translations.py`: adicione `"fr"` em `SUPPORTED`; crie o dicionário `_FR`
   traduzindo **todas** as chaves de `_EN` (use `_EN` como gabarito); registre em
   `_TABLES = {"en": _EN, "es": _ES, "fr": _FR, "pt": _PT}`.
2. Crie a bandeira `static/flags/fr.svg`.
3. `templates/base.html`: adicione `'fr': 'fr'` no dict `_flag` e mais um `<li>` no
   dropdown apontando para `set_lang('fr')`.
4. Valide a paridade de chaves antes do deploy:
   ```bash
   py - <<'EOF'
   import translations as i18n
   for lang, tbl in (("es", i18n._ES), ("fr", i18n._FR)):
       missing = [k for k in i18n._EN if k not in tbl]
       print(lang, "faltando:", missing or "OK")
   EOF
   ```

> Toda nova string visível deve entrar via `_()`/`t()` **e** receber tradução em
> `_EN` e `_ES` (e nos demais idiomas), senão cai no *fallback* (mostra o PT).
